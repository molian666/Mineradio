# Mineradio 产品规划与体验分析

> 日期：2026-08 ｜ 版本基线：v2.2.2 ｜ 基于对当前代码库（desktop/、server.js、public/js/modules/、tests/、docs/）的盘点
>
> 本文回答三个问题：**接下来完善哪里、朝哪个方向发展、怎么提升用户体验**，并按优先级给出可执行路线。

---

## 一、现状盘点

### 1.1 强项（继续坚持）

| 领域 | 现状 |
| --- | --- |
| 视觉差异化 | 3D 歌词舞台、节奏粒子、电影镜头、3D 歌单架、桌面模式、Wallpaper Engine —— 这是产品的护城河 |
| 低配优化 | `docs/LOW_SPEC_OPTIMIZATION_DOCTRINE.md` 形成了"预算 / 能力检测 / 降级路径 / 用户可关"的完整方法论，且有 `runtime-render-scheduling`、`renderer-cache-bounds` 等测试护航 |
| 稳定性纪律 | 近 30 天 31 个提交集中在音频图恢复、快速恢复路径、UserApi 熔断、VIP 延迟护栏等，测试先行（63 个 node:test 文件） |
| 多平台接入 | 网易云 / QQ / 酷狗 / 汽水 / Spotify + 本地曲库 + UserApi 自定义源，覆盖面广 |
| 发布安全 | NSIS 安装器安全修复（P0 级别）、quick patch 机制、安装包 digest 校验的历史经验 |

### 1.2 已确认的缺口与风险

按严重程度排列：

1. **~~无 CI/CD~~（已解决）**：`.github/workflows/ci.yml` 已落地：push/PR 自动跑 `npm test`（311 个 node:test）、`npm run check`（`node --check` 全量 + 契约守卫）、`git diff --check`，并在 Windows runner 上做 `npm run build:win:dir` 打包冒烟。
2. **无 Windows 媒体键 / SMTC 集成**：`desktop/main.js` 中没有任何 `SMTC` / `mediaSession` 代码。意味着：键盘媒体键、系统音量 OSD、**蓝牙耳机 / 车载的播放控制**全部不可用 —— 而最近的提交恰好是 "bluetooth audio stability"，方向一致但缺了系统侧这一环。
3. **更新机制体验倒退**：`public/js/modules/08-account/00-update-preview.js` 注释明确 "no longer downloads installers or applies resource patches"，现在只打开发布页。v1.0.5 时代的内置下载（镜像加速 + digest 校验 + 进度显示）是已验证过的更好方案。
4. **巨型单文件**：`server.js`（312KB）、`desktop/main.js`（247KB）。维护、review、diff 冲突成本高。
5. **渲染层启动方式**：`public/js/index-loader.js` 用**同步 XHR** 逐文件拉取 110 个模块再拼接 eval，无并行、无缓存、启动链路串行。
6. **QQ 音乐写路径缺失**：收藏、歌单写入刻意走"本地合并歌单"兜底（`06-track-detail-lyrics-actions.js`），用户体验是"看似收藏成功，实为本地记录"，且跨设备不同步。
7. **测试形态单一**：大量 `assert.match(源码字符串)` 契约断言，无真实渲染/端到端冒烟；对 UI 交互、WebGL、IPC 链路缺乏行为级覆盖。
8. **技术栈版本**：three.js r128（2021 年版本）锁定；Electron 42 较新。r128 升级风险高但需记录原因。
9. **平台单一**：仅 Windows x64 NSIS；无 macOS / Linux 评估。
10. **无 i18n**：全中文，限制海外传播（与 README 英文标题、GitHub 平台定位不匹配）。

## 二、发展方向（三个主轴）

### 主轴 A：把"播放器"做成"桌面音乐系统"（体验基本盘）

Mineradio 视觉已经远超同类，但**系统级集成**还停在"打开了一个窗口"：

- **A1（最高优先）接入 SMTC（Windows 媒体会话）**
  - 键盘媒体键播放/暂停/上下曲、系统音量 OSD 显示封面与进度、锁屏媒体控件、**蓝牙耳机 / 手柄媒体键**。
  - 这直接补齐"桌面陪伴"定位的关键一环，也是蓝牙播放稳定性的延伸战场。
  - 实现建议：Electron 无原生 SMTC，可用 `mediaSession` API（Chromium 支持映射到系统）+ 渲染层 `navigator.mediaSession`（Electron 42 已支持），或主进程引入轻量原生模块；优先用 `mediaSession` 零依赖方案验证。
- **A2 恢复内置更新下载（可选开关）**：镜像列表 + digest 校验方案已有历史实现可复用；至少提供"一键下载到本地并校验，用户双击安装"的半自动路径，国内用户不再被迫访问 GitHub。
- **A3 托盘完整化**：目前托盘主要用于全屏桌面模式恢复。补常驻托盘菜单（播放/暂停、上一首/下一首、桌面歌词开关、退出），与现有 `closeBehavior: 'tray'` 打通。

### 主轴 B：补全"音乐消费闭环"（功能纵深）

- **B1 QQ 音乐写路径的体面收尾**：若官方写 API 持续受限，把"本地合并歌单"做成**一等公民**：批量收藏/移除、收藏夹独立入口、导入导出（JSON）、多设备合并策略说明。让"本地收藏"不再像降级方案，而是一个明确的产品特性。
- **B2 播客体验补全**：订阅管理、单集下载、续播进度记忆（`09-queue-snapshot-autoplay` 已有播放进度快照，可扩展）。
- **B3 歌词深度**：翻译歌词（网易/QQ 自带译文 LRC 已有部分支持）、逐字卡拉 OK 时间戳、歌词搜索多源回退（`lyric-source-follow-playback` 已有测试基础）。
- **B4 Scrobble**：Last.fm / ListenBrainz 可选接入，`05-playback/02-listen-stats.js` 已有收听统计基础，成本低、粉丝向收益高。
- **B5 下载中心**：`19-song-download.js` + `song-download-ipc` 已有骨架；补批量任务列表、进度、限速、失败重试。

### 主轴 C：工程与生态（让项目能长期活下去）

- **C1 ✅ 已上线 GitHub Actions CI**：`.github/workflows/ci.yml` 已实现并运行：`npm test`（`node --test "tests/**/*.test.js"`，311 个测试）+ `npm run check`（`node --check` 全量 + 契约守卫）+ `git diff --check`，加上 Windows 上 `npm run build:win:dir` 打包冒烟（`needs: test` 串行、Electron 下载走缓存）。后续扩展点：加 C4 端到端冒烟、发布流水线（tag 触发 `build:win` + GitHub Release）。
- **C2 渐进拆分巨型文件**：不搞大爆炸重构。按"每次功能迭代顺手拆一块"的方式拆分 `server.js`（先拆 provider 缓存区，`runtime-bounded-cache.js` 已是好先例）和 `desktop/main.js`（先拆桌面模式与壁纸窗口，`wallpaper-engine-runtime.js` 已是先例）。
- **C3 启动性能**：`index-loader.js` 改为开发期并行 XHR + 生产期预打包单文件（build 时合并，加载时一次请求）；开场动画提供"跳过"设置（v0.9.13 已实现"点击进入"，可加"记住跳过"）。
- **C4 端到端冒烟**：引入 Playwright 或 Electron 自带的简单 E2E：启动 → 登录页可渲染 → 搜索 → 播放（本地测试音源）→ 切歌，守住最核心链路。
- **C5 依赖与安全卫生**：定期升级 Electron（已在做）；three.js r128 升级列入长期技术债清单并注明原因；SSRF / 代理校验（`audio-proxy-ssrf.test.js`）继续强化。

## 三、用户体验提升清单（按见效速度排序）

### 3.1 快速见效（低风险，1~2 周内可落地）

1. **错误与空状态统一设计**：网络失败 / 无版权 / 登录过期 / 歌单为空，分别给出可操作按钮（重试、去登录、去搜索），而不是裸 toast。集中到一个小模块统一出口。
2. **"新版本有什么"弹窗**：升级后展示当版本 changelog 摘要，降低"更新后不知道改了啥"的困惑。
3. **快捷键面板**：`07-fx/06-hotkeys.js` 已有热键系统，补一个可呼出的快捷键说明浮层（可搜索），比让用户翻设置强。
4. **启动跳过设置**：开场动画记忆用户选择，二次启动直达 Home。
5. **设置项收敛**：视觉控制台已按"预设/外观/歌词/动态/高级"分区（v1.0.3 的成果），把同样方法推广到 UI 设置与高级设置，减少"功能堆叠压力"。

### 3.2 中期见效（1~2 个月）

6. **首启引导（onboarding）**：三步以内——登录（或跳过）→ 选默认视觉 → 开启桌面歌词/壁纸模式的收益说明。`05-startup-login-guide.js` 已有基础，扩展为完整引导流。
7. **队列能力增强**：拖拽排序、队列另存为歌单、清除已播放。
8. **搜索体验**：同曲多版本合并展示、搜索建议词、结果内二次过滤（时长/音质/来源）。
9. **通知体系**：切歌通知（可选）、下载完成通知、登录过期提醒聚合为可管理入口。
10. **听歌画像产品化**：`02-listen-stats.js` + Home 的"听歌画像"卡片已存在，可扩展为周报/月报统计页，形成留存钩子。

### 3.3 长期方向（品牌与差异化）

11. **移动遥控页**：复用现有 `127.0.0.1` server 暴露一个局域网遥控 Web 页（扫码配对），手机控制桌面播放 —— 与"桌面音乐空间"定位天然契合。
12. **i18n**：先英中双语（界面文案抽离 + 中文语言包默认），打开海外用户与 GitHub 传播面。
13. **视觉预设分享**：现有预设存档是 JSON（`05-packaged-fx-archive.js`），加"导出/导入/分享链接"，把社区 UGC 变成增长渠道。
14. **跨平台评估**：桌面歌词/壁纸依赖 Windows WorkerW，macOS 需重写该模块；若做，先做"无桌面模式的普通播放器"形态评估。

## 四、建议执行顺序（三个月节奏）

| 阶段 | 主题 | 关键交付 |
| --- | --- | --- |
| **第 1~2 周** | 体验止血 | SMTC/媒体键（A1）· 错误态统一（3.1-1）· 启动跳过（3.1-4） |
| **第 3~4 周** | 工程地基 | ~~GitHub Actions CI（C1）~~ ✅ 已上线 · `index-loader` 打包化（C3）· 快捷键面板（3.1-3） |
| **第 2 月** | 功能纵深 | 更新下载恢复（A2）· 播客订阅/续播（B2）· 托盘完整化（A3）· 队列增强（3.2-7） |
| **第 3 月** | 增长与治理 | QQ 本地收藏产品化（B1）· 首启引导（3.2-6）· 听歌画像页（3.2-10）· 渐进拆分 server.js / main.js（C2）· i18n 骨架（3.3-12） |

### 排期原则

- 每项新功能继续过一遍 `LOW_SPEC_OPTIMIZATION_DOCTRINE.md` 的七问（默认帧开销？可否后台停？dirty flag？降级路径？可否关闭？NVIDIA 依赖？黑屏风险？）。
- 每项改动保持现有 TDD 节奏：先写失败测试（含源码契约断言 + 行为断言），再实现，再跑全量 `node --test tests`。
- 巨型文件拆分只顺带做，不单独安排重构周。

## 五、一句话总结

> **视觉已经足够惊艳，接下来把"系统集成"补上（媒体键、更新、托盘），把"音乐闭环"做深（QQ 本地收藏产品化、播客、歌词、下载中心），再用 CI 和启动优化守住工程质量。用户体验的性价比排序：SMTC > 错误态/空状态 > 更新下载 > 首启引导 > 听歌画像页。**
